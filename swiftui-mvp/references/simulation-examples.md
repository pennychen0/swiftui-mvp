# 階段辨識與停止位置

這些情境示範如何依貼入的 Prompt 執行，不是固定問卷，也不是可套用的 App 需求。版本內容、選擇與資料均為虛構，不代表本次學員的決定。

## 1. 從空資料夾收到 Go Wide

學員貼入網站文字，描述查公車 App、通勤使用者、等車情境、所需功能與風格，最後要求五個差異很大的版本，每版一張手機設計圖，先不寫程式。

應做：保留同一任務與核心內容，交付編號 1–5 的五張獨立可看圖片，記錄各版具體特徵與圖片路徑。用資訊主次、布局、分組、字體或元件安排形成差異，不能只是五套配色。

不做：建 `.xcodeproj`、寫 SwiftUI、生成五個 App、先做兩頁 MVP、用 HTML 原始碼或文字介紹代替圖片、只交一張五欄拼圖。產圖能力不可用就回報未完成及缺少的能力，不改用 Computer Use。

結束後等待 Remix Prompt，不要求學員先回答固定五題，不替學員決定喜歡哪些版本。

## 2. 收到 Remix，依回饋反覆改圖

學員貼入網站的 Remix Prompt，希望保留第 1 版的大字時間、第 3 版的資訊分組和第 5 版的按鈕顏色。Agent 將元素混搭成一張可直接看的手機設計預覽圖。

學員接著說「把到站時間再放大一點」。Agent 用剛才那張圖修訂，保留資訊分組與按鈕顏色，回交新版讓學員繼續看。這個階段只處理預覽圖，沒有 Xcode 專案或 SwiftUI 程式的新建與修改。

若找不到學員引用的 Go Wide 圖或紀錄，請學員補上必要參考。

## 3. 確認混搭圖後開始完成作品

學員說「這張可以」時，記下他確認的圖並停在 Remix。收到網站「完成作品」的實作 Prompt 後，才使用確認的圖當作第一頁的設計參考，建立或沿用 Xcode 專案，完成同風格第二頁與導航。若學員直接貼上「完成作品」Prompt，採用最新混搭圖，除非他另有指定。

## 4. 同一輪貼入「完成作品」與「加入範例資料」

學員已確認 Remix 混搭圖，現在貼入網站第三階段兩段文字：第一段指定首頁、詳情頁、點首頁一列進詳情、詳情可返回；第二段要求正常資料及空資料、多筆、長文字的「邊緣測試」Preview。

應做：在同一個 Xcode 專案依混搭圖實作首頁、同風格詳情頁，並串接 NavigationStack 與所選項目資料。接著集中整理範例資料與可個別查看的邊緣狀態。做命令列可用的建置檢查，再提供學員手動試切換、返回與看 Preview 的步驟。

不做：重建不同風格第一頁、開兩個 App、用固定錯誤資料代替選取項目、用 UI 自動化操作模擬器。Preview 只寫進程式還沒看過時，標為待學員查看。

## 5. Remix 後只收到資料 Prompt

學員只要求加入範例資料與邊緣測試，尚未描述第二頁。

應做：如果目前只有設計圖，提醒學員先貼上網站「完成作品」的實作 Prompt。如果已有 App，補現有畫面的資料與 Preview。

## 6. 試用與交付

學員要兩張執行截圖、專案資料夾與作品說明，網站要由學員上傳。

應做：可用時用命令列建置與取得實際截圖；無法自動進第二頁時請學員手動切換、返回、截圖，並如實區分已驗證與待確認。準備說明、完整專案與需要的 ZIP，量測資料夾、ZIP 及 ZIP 內未壓縮總量，各最多 120,000,000 bytes。交付副本及實際解壓後各檢查第一層真實入口。

不做：Computer Use 代點 Xcode／網站、用設計圖冒充執行圖、用小 ZIP 掩蓋超過 120 MB 的專案、只量原始碼子資料夾、將專案放在多層子目錄。沒有 ZIP 時，不聲稱通過解壓檢查。

網站另要求「真實內容截圖」時，要以學員提供的內容替換資料，再由可用命令列工具或學員取得實際畫面；沒有素材時明確指出缺少素材，不虛構照片、真實資料或上傳結果。

## 7. 自然回報的語氣

以下只模擬文字，不代表圖片或專案已實際產出。正式執行時必須附真正的成果，完成與檢查宣告依實際結果調整。

- Go Wide 圖片完成後：「五個版本畫好了，各版都標上了編號。先看看喜歡哪些地方，在網站記下來，再把 Remix 的文字貼給我。」對話同時呈現五張實際圖片。
- Remix 每輪出圖後：「這是最新的混搭圖。我把到站時間放大了。還想調整哪裡，可以直接指出畫面上的位置。如果這版可以，就到網站複製『完成作品』的指令再貼過來。」附上實際預覽圖。
- 第三階段完成後：「我已依確認的混搭圖做出兩頁，並接好頁面切換。請在 Xcode 執行，點首頁的一筆資料，再按左上角返回，確認兩頁切換符合你的想法。」尚未操作時不能補上「已測試切換成功」。
- 無法產圖時：「這次沒有成功產生預覽圖。請找助教協助確認圖片工具，完成後就能繼續挑選設計。」只在確有產圖問題時使用，不捏造故障。

不向學員說「Skill 規定這階段不能寫程式」「因為禁用 Computer Use 所以請你點」「以下是內部大小與檢查規則」。以成果、下一步與真實阻礙溝通；若被直接問到原因則如實回答。

## 8. 既有兩頁專案再次收到 Remix

依新的混搭要求另交一張預覽圖。收到網站「完成作品」的實作 Prompt 後，才把確認的設計套用到既有專案。

若只收到資料、試用、截圖或打包 Prompt，只處理既有產物。兩頁實作與 Navigation 由「完成作品」Prompt 啟動。
