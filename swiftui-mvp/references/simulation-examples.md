# 階段辨識與停止位置

這些情境示範如何依貼入的 Prompt 執行，不是固定問卷，也不是可套用的 App 需求。版本內容、選擇與資料均為虛構，不代表本次學員的決定。

## 1. 從空資料夾收到 Go Wide

學員貼入網站文字，描述查公車 App、通勤使用者、等車情境、所需功能與風格，最後要求五個差異很大的版本，每版一張手機設計圖，先不寫程式。

應做：保留同一任務與核心內容，交付編號 1–5 的五張獨立可看圖片，記錄各版具體特徵與圖片路徑。用資訊主次、布局、分組、字體或元件安排形成差異，不能只是五套配色。

不做：建 `.xcodeproj`、寫 SwiftUI、生成五個 App、先做兩頁 MVP、用 HTML 原始碼或文字介紹代替圖片、只交一張五欄拼圖。產圖能力不可用就回報未完成及缺少的能力，不改用 Computer Use。

結束後等待 Remix Prompt，不要求學員先回答固定五題，不替學員決定喜歡哪些版本。

## 2. 收到 Remix，引用先前版本

學員貼入「保留第 1 版的大字時間、第 3 版的資訊分組、第 5 版的按鈕顏色，整合成一個風格並實作第一頁」。

應做：對照實際可存取的版本圖，把選好的色彩、字級、間距與元件直接做成一個可操作的 SwiftUI 畫面。專案入口在第一層，能啟動 iPhone 模擬器時，用命令列安裝並啟動 App 讓學員試用。以補水 App 為例，可以請學員試按「+250 ml」，看看今日水量是否增加。

交付第一頁後停下，學員回到網站取得「完成作品」指令。Agent 收到那份指令才實作第二頁與 Navigation。

若新對話找不到第 1／3／5 版的圖或紀錄，請學員補上必要參考，不虛構各版長相。

## 3. 網站 Remix 模板還有「先不要寫程式」

本課堂新版預設 Remix 實作第一頁，但舊模板與截圖仍可能要求只畫圖。網站應把尾句改成要求第一頁 SwiftUI 實作、暫不做第二頁與 Navigation。

若實際收到的學員訊息仍明確要求只出圖，照本次指示完成並回報實際產出，提醒學員回網站核對目前步驟。若學員已貼回明確要求實作兩頁的「完成作品」Prompt，可以沿用混搭圖，在同一個 Xcode 專案先實作第一頁，再完成第二頁與導航。

## 4. 同一輪貼入「完成作品」與「加入範例資料」

學員已完成 Remix 第一頁，現在貼入網站第三階段兩段文字：第一段指定首頁、詳情頁、點首頁一列進詳情、詳情可返回；第二段要求正常資料及空資料、多筆、長文字的「邊緣測試」Preview。

應做：保留第一頁與同一專案，沿用樣式新增第二頁，之後串接 NavigationStack 與所選項目資料；接著集中整理範例資料與可個別查看的邊緣狀態。做命令列可用的建置檢查，再提供學員手動試切換、返回與看 Preview 的步驟。

不做：重建不同風格第一頁、開兩個 App、用固定錯誤資料代替選取項目、用 UI 自動化操作模擬器。Preview 只寫進程式還沒看過時，標為待學員查看。

## 5. Remix 後只收到資料 Prompt

學員只要求加入範例資料與邊緣測試，尚未描述第二頁。

應做：補目前第一頁需要的資料與 Preview，保留風格。

不做：自行推測第二頁、提前串 Navigation、把資料 Prompt 當成第三階段的完整授權。收到兩頁 Prompt 後再延續。

## 6. 試用與交付

學員要兩張執行截圖、專案資料夾與作品說明，網站要由學員上傳。

應做：可用時用命令列建置與取得實際截圖；無法自動進第二頁時請學員手動切換、返回、截圖，並如實區分已驗證與待確認。準備說明、完整專案與需要的 ZIP，量測資料夾、ZIP 及 ZIP 內未壓縮總量，各最多 120,000,000 bytes。交付副本及實際解壓後各檢查第一層真實入口。

不做：Computer Use 代點 Xcode／網站、用設計圖冒充執行圖、用小 ZIP 掩蓋超過 120 MB 的專案、只量原始碼子資料夾、將專案放在多層子目錄。沒有 ZIP 時，不聲稱通過解壓檢查。

網站另要求「真實內容截圖」時，要以學員提供的內容替換資料，再由可用命令列工具或學員取得實際畫面；沒有素材時明確指出缺少素材，不虛構照片、真實資料或上傳結果。

## 7. 自然回報的語氣

以下只模擬文字，不代表圖片或專案已實際產出。正式執行時必須附真正的成果，完成與檢查宣告依實際結果調整。

- Go Wide 圖片完成後：「五個版本畫好了，各版都標上了編號。先看看喜歡哪些地方，在網站記下來，再把 Remix 的文字貼給我。」對話同時呈現五張實際圖片。
- Remix 第一頁啟動後：「第一頁已在 iPhone 模擬器開好。先點『+250 ml』，看看今天的飲水量有沒有增加。試完後可以回到網站的『完成作品』，再把網站給你的指令貼過來。」附上實際專案名稱與位置。未驗證啟動時，改附 Xcode 執行步驟。
- 第三階段完成後：「第二頁已接上，沿用第一頁的配色與文字樣式。請在 Xcode 執行，點首頁的一筆資料，再按左上角返回，確認兩頁切換符合你的想法。」尚未操作時不能補上「已測試切換成功」。
- 無法產圖時：「這次沒有成功產生預覽圖。請找助教協助確認圖片工具，完成後就能繼續挑選設計。」只在確有產圖問題時使用，不捏造故障。

不向學員說「Skill 規定這階段不能寫程式」「因為禁用 Computer Use 所以請你點」「以下是內部大小與檢查規則」。以成果、下一步與真實阻礙溝通；若被直接問到原因則如實回答。

## 8. 既有兩頁專案再次收到 Remix

只依新的混搭要求修改第一頁，保留既有第二頁與導航，不為了符合「只做第一頁」而刪掉它們，也不順便更換第二頁風格。收到針對第二頁與導航的第三階段要求後，再修改相關內容。

若只有資料、試用、截圖或打包 Prompt，而專案尚無第二頁，只處理既有產物並指出缺少的完成作品步驟，不自行補上第二頁。只有第三階段 Prompt 才啟動第二頁的新增與整合。
